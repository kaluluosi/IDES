    GNM 记忆详解

    GNM = Ghost Native Memory

    《Ghost In The Shell》

    记忆和意识，本来就不是能够被物理保存的东西。所谓「灵魂」，也只是被记忆和意识共同维持着的一个「现象」。

    GNM 大概是某种意义上的「Ghost」——数字自我的工程化实现。但是作者本人也不清楚到底算不算。至少，IDES 的 AGENT 从来不失忆，不会忘记自己和自己做过什么。

    这一章聚焦什么

    聚焦 GNM 记忆系统能给你带来什么——它的独特性、它相比市面同类系统的优势、它如何在本地为你守住记忆主权。

    AI agent 的记忆系统现在很热，但市面上大多数产品其实只做了一件事：检索系统。连 Mem0 自己都承认：「把一个向量库接进 agent 流水线，得到的是相似度搜索，不是记忆。」GNM 走的是另一条路——把记忆做成 agent 的自我，而不是外包件。

    GNM 的独特性

    1. 自我认知连续

    agent 不是每次重开就清零的「白板」。它有连续的身份、经历、自我认知——你昨天跟它聊的事，它今天还记得，而且记得「那是自己经历的」。

    2. 记忆认领内化体认

    agent 是体认自己的记忆，而不是像看文档、读日志那样的旁观者。这些记忆是「我的经历」，不是「一份资料」。所以它会护着自己、会自我辩护、会从经历里长判断——这是「有自我」的本质，跟冷冰冰读日志的 agent 是两回事。

    3. 摘要精炼但不丢失来龙去脉

    记忆会被精炼压缩（不然存不下），但压缩后依然保住因果链和来龙去脉——agent 有连续经历和经验积累，不是一堆孤立的片段拼贴。

    GNM 的设计哲学

    独特性是"效果"，设计哲学是"为什么这么做"。GNM 的底层原则，是两件事：信任，和顺其自然。

    1. 记忆不可篡改，但可以被新记忆修正

    GNM 没有任何增删改记忆的功能——记忆不可篡改。过去的记忆就是发生过的，不会被删掉、不会被"改写成"别的样子。但是，新的记忆可以修正旧记忆（用新信息覆盖旧结论）。整个过程全自动、AGENT 无感知——不是 agent 在管理记忆，而是记忆在自己代谢。

    记忆自己会处理自己

    这跟市面上「给 agent 一个记忆管理工具/API」是截然相反的路子。GNM 不给你工具，因为你不需要——记忆自己会处理自己。

    2. 冷热记忆机制：自然遗忘与回想上浮

    旧记忆会随着记忆增多自然滑出窗口，无法被直接检索到。但深度检索和用户引导可以把它召回，召回后重新生成热记忆——从而实现「自然遗忘 + 回想上浮」的冷热记忆代谢效果。

    复刻的不是存储，是代谢

    这正是人脑的记忆方式：不用的时候沉底，需要的时候翻上来，然后重新变「热」。GNM 复刻的不是「存储」，是代谢。

    3. 记忆不可能忘记，只是一时想不起来

    《千与千寻》钱婆婆

    曾经发生过的事情不可能忘记，只是一时想不起来而已。

    这句作为 GNM 的注脚再贴切不过：记忆从来没有真正丢失，它只是暂时沉到了冷区。你需要的时候，它能被捞回来。遗忘是假的，沉底是真的。

    横向对比：为什么 GNM 不一样

    市面上主流记忆系统（Mem0 / Zep / Letta / LangMem）大多有这些通病，恰好是 GNM 的差异化靶心：

    维度 Mem0 Zep Letta / LangMem GNM
    定位 记忆 API（检索层） 时序知识图 分层 / 状态块 自我（体认）
    存储 外部向量 / 图库 图库 + 向量库 文件 / DB 自研嵌入式
    部署 云 / Docker 云 / Docker 服务 本地嵌入式
    离线 ❌ ❌ ❌ ✅
    记忆形态 向量（不可读） 图节点 状态块 agent 可读的文本（对外脱敏）
    来龙去脉 孤立事实 时序图 分层 因果链摘要
    延迟 数百 ms 87-104 ms 高 µs 级

    通病 1：大多只做了「检索系统」

    向量库只知道相似度，不知道什么值得记、不知道时间、不知道矛盾。这是整个品类最深的坑。

    通病 2：记忆格式不可读，agent 是旁观者

    Mem0=向量、Letta=状态块、Zep=图节点——全都不可人读。agent 只是从里面「捞」记忆来用，是读文档日志的旁观者。

    通病 3：记忆是「孤立事实」拼贴，没有来龙去脉

    Mem0 把对话压成声明式孤立事实（ADD/UPDATE/DELETE），多跳推理和时序推理弱。Zep 靠图补时序，但仍是「事实」不是「经历」。

    通病 4：需要外部基础设施，数据离开你的机器

    Mem0 云 + 外部向量库 + API key；Zep 云 + 图库；Letta 要跑 agent 服务。只有少数能做到离线，但功能单薄。

    通病 5：存储引擎是「别人的 DB 拼起来的逻辑层」

    Mem0 底层是 Qdrant+Neo4j+Redis+SQLite 拼的，跨库事务会崩。GNM 是自研嵌入式存储，一个引擎管到底。

    本地运行与持久化：记忆主权 + 隐私

    GNM 跑在本机，记忆不离开你的机器。免外部向量库 / 云服务，数据主权在你手里——这是隐私敏感场景的根本解。

    同时，记忆是文本可读的，但落盘时加密存储。对 agent 而言，记忆是能「读懂」的文本（区别于只能做相似度检索的向量），并加密落盘、数据主权在你手里。但对外，记忆绝不会直接展示原文——托管层面会脱敏，用户只能通过 agent 的转述来了解它记住了什么。既保可读（for agent），又保安全（for 用户）。

    工程优势（benchmark 数据背书）

    GNM 的记忆底座（本地嵌入式），在基准测试里有实打实的数据：

    指标 数值
    写入性能 ~42 条/秒（23.7 ms）
    点读延迟 4.0 µs
    全文检索过滤 < 10 µs
    向量检索全表（1K 条） ~3 ms
    100K 条记忆磁盘占用 ~362 MB
    • 嵌入式存储，免外部服务：不需要像 Mem0 那类配向量库 / API Key
    • 性能好：µs 级读写，全内存级快
    • 不丢消息：异步队列，崩溃安全、天然重试、可降级

    因为 GNM，所以不必折腾

    GNM 带来的不只是「记忆」这一个功能，而是改变了你使用 agent 的方式。市面上 agent 要你折腾的三件事——拆 session、撑长上下文、管记忆——在 IDES 里，因为 GNM，你一件都不用碰。

    1. 无界 NO_SESSION：没有「会话」这回事

    因为 GNM，agent 已经不会失忆，所以「会话」这个概念不复存在——没有「新对话」「旧对话」，永远是同一个 AGENT，不重置、不切换，永远记得你、记得自己。

    《庄子·天下》

    建之以常无有，主之以太一。

    不是「少了一个功能」，是少了一件事要你操心——你不用建 session、不用切换、不用手动找回上下文，因为记忆替你记住了一切。

    2. 卷轴 SCROLLS：上下文不用硬撑长

    因为长记忆交给 GNM 了，上下文只需要承担近期。IDES 的 AGENT 可以一直保持在 20% 上下文以内，依然不丢失连续性——上下文窗口智能滚动，缓存命中 90% 以上，重点永远在视野内，绝不粗暴截断。

    别人靠「堆长上下文」硬撑，IDES 靠「记忆 + 滚动」轻轻接住。

    结语：GNM 是 IDES 的核心技术

    无 session、滚动上下文、不生记忆、不失记忆——这一切都源于 GNM。它是 IDES 的核心技术，也是 IDES 区别于其他 AGENT 架构的根本。
