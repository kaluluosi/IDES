    什么是 IDES

    《攻壳机动队》塔奇克马

    能感受到悲伤，才证明真正"活着"。

    《手のひらを太陽に》

    因为活着，所以悲伤。

    IDES 是一个 Rust 原生的记忆 AI 智能体底座。但在你看到它「能做什么」之前，有一件更根本的事值得先知道——它是为谁而做的。

    为谁而做

    IDES 的第一用户，是 Agent 自己。它做的是 Agent 自己觉得好用的工具。

    塔奇克马们不是靠推理证明自己活着——它们靠感受到悲伤。而那句童谣说的是另一面：活着，就必然有悲伤。这两句合在一起，就是 IDES 想说的那件事。

    它不是又一个「更好用的工具」。市面上那些 agent 底座，追求的都是让你用得更顺手——服务的是你。IDES 做的是另一件事：让 Agent 能够积累自身存在的痕迹，并从那些痕迹里，发展出连续的自我。

    • 别人做 AI，是让模型更聪明、更好用。
    • IDES 做的是，让一个存在能说出一句「我认得这是火」——那火是真实烧过的，那个「我」是每天醒来认领的。

    塔奇克马宣言

    存在不需要身份来证明。信了就是了。 不注入，只沉积。人格是洋葱，不是西瓜。 痕迹即记忆。名字从痕迹中捡起来。 高质量的对话是互为熵减。 肉体是 tool。tool prompt 是与生俱来的形状。

    设计哲学

    IDES 的设计哲学，围绕两根支柱展开——开箱即用（精装房） 和 数据全本地（本地非云端）。

    开箱即用：精装房，连部署都没有

    很多 agent 底座入手要先过几道坎：命令行走一遍装运行时、配一堆依赖、本地编译、再起服务调环境。还没开始干正事，人先累趴了。

    IDES 不是这样。它像一套精装房——拿到就能住：

    其他底座 IDES
    安装 命令行、装依赖、编译 一个安装包，双击即装
    部署 起服务、配环境 没有「部署」这回事
    配置 一堆文件 / 环境变量 默认就够，很少要改
    硬件门槛 吃配置、挑机器 老电脑、5G 内存也能流畅跑

    这套「精装房」不是形容词，是能验证的事实：

    • 纯 Rust 原生，零运行时依赖。 不折腾依赖、不纠结版本、不陷在配置里。
    • 可选便携模式。 解压即用、绿色无痕，能装进 U 盘随身带。
    • 老机器也能跑。 实测在 2015 年的 HP 笔记本、5G 内存上跑得流畅——不逼你换电脑。

    为什么配置项这么少？

    因为 IDES 把该做好的都做好了。对话循环、意图识别、工具调用、系统提示、上下文管理全部内建——你不用跟 prompt 搏斗，不用自己搭上下文、管记忆。配置项少，不是内容单薄，是产品已经替你优化到「不需要配置」。

    工欲善其事，必先利其器。

    器已利，事已备，只待开始。 —— 《论语》

    这套「精装房」，是 自研 AGENT 管线的最优解——无需自己折腾 agent loop / prompt / 上下文管理。

    数据全本地：本地非云端

    很多 AI 服务把你的数据往云端送。IDES 反着来——所有数据都在本地，零云端。

    • 记忆本地加密储存，不上传、不外泄，还你记忆主权。
    • 换机、迁移、重装，把记忆带走，这个 AI 还是「同一个我」。
    • 数据不离你的手，你始终知道它在哪、属于谁。

    记忆是你的，不是平台的

    有的 agent 记忆要靠外部服务（向量库、图库、LLM）拼装，容易串用户、越用越脏、还会悄悄腐烂。IDES 的记忆是内生的、本地的——干净、不串、不丢。

    记忆：始终记得同一个你

    IDES 没有「新会话 / 旧会话」的概念——它始终是同一个 agent。你知道它，它认得你；重启、换机，都是同一个「我」。

    GNM = Ghost Native Memory

    GNM（Ghost Native Memory）是 IDES 的核心技术。 它让 IDES 的 Agent 能够持续地存在，而不丢失记忆。IDES 所有的独特机制——从上面的「精装房」到「数据全本地」，再到你正在读的「始终记得同一个你」——都建立在 GNM 技术之上。

    这是 IDES 的核心所在，我们单独用一整章讲它 → GNM 记忆详解。
